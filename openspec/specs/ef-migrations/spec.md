## ADDED Requirements

### Requirement: Design-time DbContext factory

The Infrastructure project SHALL include an `IDesignTimeDbContextFactory<MarqueDbContext>` implementation that loads connection settings from the API project's configuration files and environment variables.

#### Scenario: EF CLI can add migrations

- **WHEN** running `dotnet ef migrations add` with startup project `Marque.Api` and project `Marque.Infrastructure`
- **THEN** the command succeeds without requiring the API host to be running

### Requirement: Initial migration matches PRD schema

The solution SHALL include an initial EF Core migration that creates all application tables, foreign keys, and indexes defined in PRD section 5.2.

#### Scenario: Migration creates core tables

- **WHEN** applying the initial migration to an empty PostgreSQL database
- **THEN** tables `stores`, `professionals`, `weekly_hours`, `services`, `service_professional`, and `appointments` exist

### Requirement: RLS documented separately from EF

Row Level Security policies from PRD section 5.3 SHALL NOT be generated by EF migrations; they SHALL be documented for manual application in Supabase (SQL script or README instructions).

#### Scenario: Migration does not enable RLS

- **WHEN** applying only the EF initial migration
- **THEN** RLS is not enabled on tables until the separate Supabase SQL script is executed

### Requirement: Migration workflow documented

The README SHALL document commands to add, apply, and roll back migrations against Supabase or local PostgreSQL, including the need for a valid `ConnectionStrings:Supabase` value.

#### Scenario: Developer applies schema locally

- **WHEN** a developer follows README migration steps with a configured connection string
- **THEN** `dotnet ef database update` applies the schema successfully
