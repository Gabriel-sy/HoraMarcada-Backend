## Why

The backend foundation established domain entities and repository ports, but nothing persists to PostgreSQL yet. The PRD defines the full schema on Supabase (tables, indexes, and RLS). Without an EF Core `DbContext`, fluent configurations, and an initial migration, no feature work (store CRUD, public booking, availability) can read or write data. This change wires the Infrastructure layer to Supabase PostgreSQL so the API can use real persistence in subsequent changes.

## What Changes

- Add `MarqueDbContext` with `DbSet`s for all PRD tables: stores, professionals, weekly_hours, services, service_professional (join), appointments
- Implement EF Core entity type configurations (fluent API) mapping domain entities to PRD column names, types, constraints, and relationships
- Add value converters for domain value objects (`Slug`, `PhoneNumber`, `Money`) and enums (`AppointmentStatus`)
- Register `DbContext` and connection options in `AddInfrastructure()` using Supabase PostgreSQL connection string from configuration
- Add EF Core design-time factory for CLI migrations (`dotnet ef migrations add`)
- Generate initial migration aligned with PRD section 5.2 (tables and indexes); RLS policies remain in Supabase SQL (documented, not generated by EF)
- Implement EF Core repository classes for Application ports (`IStoreRepository`, `IProfessionalRepository`, `IServiceRepository`, `IAppointmentRepository`)
- Extend `appsettings` / environment variable contract for Supabase database URL
- Add README section for local migration apply and Supabase connection setup

## Capabilities

### New Capabilities

- `ef-dbcontext`: Application `DbContext`, `DbSet` registration, PostgreSQL provider, and DI registration
- `ef-entity-configurations`: Fluent API mappings, owned types/converters for value objects, relationships and indexes per PRD
- `ef-migrations`: Initial EF migration and design-time tooling; apply instructions for Supabase
- `ef-repositories`: Concrete EF implementations of Application repository interfaces

### Modified Capabilities

- _(none — persistence is new; domain-model requirements unchanged)_

## Impact

- **Code**: `Marque.Infrastructure` (Persistence folder: DbContext, Configurations, Repositories, Migrations); `InfrastructureServiceCollectionExtensions`; optional `Marque.Api` appsettings
- **Dependencies**: `Microsoft.EntityFrameworkCore.Design` (tools), possibly `Microsoft.Extensions.Configuration` packages for design-time factory
- **Systems**: Supabase PostgreSQL project must exist; connection string required at runtime and for migrations
- **Out of scope**: Supabase Auth JWT middleware, RLS policy SQL execution via EF, API endpoints, Hangfire schema, integration tests against live Supabase
